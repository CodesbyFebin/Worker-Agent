# Worker Agent Topical Authority Map

Status: **planning only / not automatically indexable**

This document turns the requested 30-pillar × 10-cluster structure into a publish-safe topical graph for AI Worker Agents. It is a content architecture, not permission to generate 300 thin pages.

## Domain rule

The current product repository uses `workeragent.cloud` as its public product host. `workeragent.in` is treated here as a requested expansion/candidate host only. Do not change canonicals, sitemap hostnames, redirects, or `hreflang` until an explicit domain relationship is approved.

## Entity scope

Primary entity: **AI Worker Agent** / **Autonomous Digital Worker**.

Primary supporting entities: agent runtime, missions/tasks, orchestration, tools/MCP, model routing, memory/state, queues, event streaming, governance, evidence, human approval, observability, self-hosting, content operations, coding agents.

Avoid drifting into unrelated staffing, generic robotics, self-driving vehicles, drones, or smart-city OS content unless Worker Agent has a real product/use-case relationship and the page adds standalone value.

## Surface model

Each pillar should eventually expose a balanced mix of:

- **Learn** — canonical definitions and concept pages
- **Docs** — technical implementation and architecture
- **Blog** — evidence-backed analysis, use cases, and trends
- **Knowledge Base** — troubleshooting and operational answers
- **FAQ** — user-facing questions, only when the visible page genuinely answers them
- **Comparison** — neutral, sourced comparisons without fabricated reviews or pricing

All clusters start in `planned` state and are excluded from the sitemap until the publication gates in `docs/seo/PUBLICATION_GATES.md` pass.
